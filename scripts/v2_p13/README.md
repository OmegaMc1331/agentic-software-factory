# P13 local qualification

Run from the repository root using disposable repositories and fresh evidence directories under `.factory/v2/p13`. Preserve failed attempts. Nothing here authorizes a remote push, PR, deployment, tag or release. V1 remains the default entry and P10 remains manual-resume with its existing 180/60-second defaults.

1. `node scripts/v2_p13/validate.mjs focused` exercises actual application preferences/project summaries/notifications, project database migration and memory invariants, and native Git index/filter guards. `rust` runs formatting, strict Clippy and the complete serial workspace suite. `parallel` runs the complete normal-threaded suite. Run one Cargo process at a time.
2. Run `frontend`, then `embedded` sequentially. `node scripts/v2_p13/stamp-build.mjs N` requires an unchanged-source successful embedded build and copies the executable to a new numbered identity, recording source/binary hashes. Do not rebuild a running Windows binary. Native caches use `./target` here; override CARGO_TARGET_DIR on another host.
3. Set `ASF_P13_BINARY` to the copied executable and `ASF_P13_OUTPUT` to a fresh directory. `browser.mjs` exercises actual registration, shared preferences, keyboard commands, CodeMirror save, selected-hunk/index/local commit, a controlled real Planner-process failure, durable notification/read state, scoped navigation, restoration, defaults, themes/viewports, keyboard-only actions and Axe. The controlled provider process is explicitly not model acceptance. It never supplies a fake production notification.
4. `mission.mjs --model` performs a fresh genuine configured Codex mission in its own repository. It requires existing available CLI authentication and the selected configured model. It retains actual Planner/Worker/read-only Reviewer ownership, memory usage, local integration and independent tests/500-case oracle. The harness writes no implementation patch and publishes nothing. Stop on provider quota refusal; no account/model/endpoint/sandbox substitution. Raw private model reasoning and credentials are not exported.
5. `mission.mjs --inspect-model`, with `ASF_P13_MODEL_SOURCE` naming a prior passed fresh P13 result, performs model-free inspection/current UI and independent code re-verification. It is not another model-driven run. `--retained` inspects retained P08 records when their databases exist; otherwise it preserves their evidence hashes and uses clearly labelled fresh controlled parallel/conflict scheduler fixtures. Real Git/process evidence from those fixtures is not relabelled genuine LLM evidence. Remote reads are opt-in (`--remote-reads`); remote writes have no acceptance flag.
6. Existing P03–P07 browser regressions run with `scripts/v2_p12/regressions.mjs`, pointing ASF_P12_BINARY at the copied P13 executable and ASF_P12_REGRESSION_OUTPUT at a fresh P13 directory. P09 setup/inspection, P10 controlled acceptance and P11 `--ui-only` retain their existing scripts and fresh P13 output overrides. Their original native model evidence remains separate. No fixtures are populated into the production development repository.
7. Set `ASF_IDE_TEST_TOOLS` to actually approved local tool profiles and run `validate.mjs tools`. Missing native tools/platforms remain unexecuted; do not suppress failures or present simulated adapters as native qualification.
8. `performance.mjs` requires ASF_P13_BINARY, its matching ASF_P13_BUILD_RECORD and fresh ASF_P13_PERFORMANCE_OUTPUT. Default inputs create 100/1,000 memories with three revisions and 100/1,000/6,000-file native Git fixtures. Preserve the same inputs/build profile and avoid concurrent ASF workloads for comparisons. `--memory-only --stress`, `ASF_P13_MEMORY_COUNTS=100,1000,10000`, `ASF_P13_GIT_COUNTS=2` uses shorter explicitly synthetic stress content; it is a separate workload, not a historical speedup denominator. API resource/secret/source/revision limits remain active.
9. On Windows, `runner-memory.ps1 -Workers 2 -OutputDirectory <fresh P13 path>` measures the complete Vitest process tree and records the actual child exit. Repeat at 4 workers; 16 workers are explicitly not started below 4 GiB free headroom. The existing two-worker configuration is retained. Summed working sets can double-count shared pages and polling can miss short peaks. A bounded-worker pass does not qualify unrestricted concurrency.

The validation runner fingerprints all crates/dashboard/build inputs and reports changed-source runs as failed qualification even if individual commands pass. Preserve that status. `source-equivalence.mjs` separately reconstructs the exact build5 fingerprint using saved original files and permits only the listed frontend delta; it proves Rust/other inputs unchanged, not that changed frontend code was tested by an earlier run. Final full frontend and current browser runs must cover the delta. Do not use equivalence to excuse Rust, permission or process changes.


The source-equivalence proof also reconstructs the build-9 boundary by restoring only the palette initial-focus component and its test. A serial runner that observed those frontend changes still retains its original FAILED aggregate status; passing Cargo commands and exact unchanged Rust inputs are separate evidence. A failed test command cannot be excused by this proof.

The collector exports selected logs/results/screenshots, actual model/Git evidence, measurements, source lineage and limitations. SQLite databases, executables, raw authentication output and raw private reasoning remain local. Verify the exported manifest before the final local delivery commit. Native Linux/macOS, remote CI, native AT and live GitHub writes remain separate P14 prerequisites.

Evidence is marked `-text` so Git preserves hashed bytes, and archival whitespace is excluded from Git's whitespace lint so raw CRLF/log/patch bytes are not rewritten. This applies only to the evidence directory; implementation, documentation and scripts retain their normal checks. The local archive unignores its exported logs, and closure verifies that every manifest file is staged. Runtime source fingerprints are byte-for-byte working-tree identities, including line endings; a different checkout/OS must not silently treat changed bytes as the same proof. It needs its own source comparison and native validation. Exported snapshots reproduce the described local boundary without normalizing away unexplained differences.

`inspect-product.mjs` reopens the completed P13 browser fixture using `ASF_P13_BROWSER_SOURCE`, verifies unchanged HEAD/index/working content, and captures the genuine remaining hunk. Its default mode additionally performs six actual Memory open/close/unmount cycles with explicit CDP garbage collection before heap samples. This is a diagnostic, not normal-render latency or proof of long-duration leak freedom. `--image-only` skips that already measured resource diagnostic. Run it separately after the controlled benchmark so it does not compete with API measurements. No model or Git mutation is requested.

After staging the delivery, run `node scripts/v2_p13/verify-evidence.mjs --git-index`. It reads actual staged blobs through bounded `git cat-file --batch` and verifies every exported byte, including the manifest. This catches ignored/missing logs or line-ending transformations before the local commit. The same check can run after commit because the index still names the delivered blobs.
