## Browser and real-agent boundary

`acceptance.mjs` uses the production Rust server and built V2 workspace. Manual mode validates CodeMirror save, genuine Git state, file/hunk staging/unstaging, exact commits, dirty drafts, clean checkout, history, reload, project isolation and themes. Model mode creates a genuine coding mission through P07 and requires an independently verified final commit. Retained mode preserves historical genuine P08 evidence separately from current controlled scheduler/browser coverage. Performance mode uses explicitly generated source data and real Git/API operations.

The retained P03-P07 browser runners remain required regression checks. Screenshots are visually inspected and accompany behavioral assertions. Fixture data alone is never called a genuine model execution.

The original P08 fixture worktrees survived but their runtime databases were unavailable at P12 qualification. The failed read attempt is preserved. P08 genuine execution JSON/hashes retain their historical meaning; they are not imported as reconstructed database history. Current parallel/dependency/conflict UI coverage uses fresh controlled Workers, real Git, the actual P08 scheduler/Planner-fixture revision path and independent final verification. Its browser-only replay preserves those newly completed records and launches no further agents. The separate P12 coding/review acceptance remains genuine model execution.

## Explicit non-qualification

Live GitHub write acceptance is NOT QUALIFIED without an explicitly authorized disposable remote mutation. Native Linux/macOS and exact-commit remote CI are independent pending release gates. First-commit parent comparison, arbitrary binary/oversized/CRLF hunk staging and destructive cleanup/history rewriting are not offered as supported actions. P11 large-library insertion performance is inherited debt; P12 ordinary Git operations do not trigger extraction or retrieve the full memory library.
