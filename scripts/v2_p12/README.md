# P12 local qualification

Use disposable local repositories and a copied embedded executable. All output belongs under `.factory/v2/p12/`; existing result files are never overwritten. No command here authorizes external publication.

1. Run `node scripts/v2_p12/validate.mjs focused`, the full `git` mode and the GitHub adapter/transport tests. Run one Cargo process at a time. The approved local cache is `./target`; override CARGO_TARGET_DIR for another host.
2. Run `frontend`, then `embedded` sequentially. Copy debug/factory.exe to a unique `.factory/v2/p12/run/` name. Set `ASF_P12_BINARY` to its absolute path. Do not rebuild an executable that is running on Windows.
3. Run `node scripts/v2_p12/acceptance.mjs`. It uses real Git and the production browser/editor/API to stage a selected hunk, preserve other source, stage/unstage files, commit exact index contents, protect drafts, switch branches and restore isolated project views. Authenticated GitHub reads use the explicitly requested ASF repository; the script performs zero remote writes.
4. Run `node scripts/v2_p12/acceptance.mjs --model` once using a fresh ASF_P12_OUTPUT. It checks CLI availability/authentication without reading credentials, invokes the configured gpt-6.1-sol profiles through the genuine mission form, reproduces a defect, observes Worker execution and requires actual read-only Reviewer approval, integration and independent checkout tests/oracle. The harness never supplies an implementation patch. Stop on provider quota refusal; never change accounts, credentials, endpoints or model identities to bypass it. CLI version and actual execution headers are retained; no private reasoning/transcript is exported.
5. `--retained` performs no model invocations. When available, it opens the original disposable P08 Parallel/Conflict databases and inspects their recorded history. If a database is gone, it preserves the original evidence hash and creates a clearly labelled fresh controlled scheduler fixture. An owned two-client loopback barrier proves actual controlled Worker overlap; real Git, reviews, dependency order, conflict, bounded Planner-fixture revision and independent repair checks are exercised. Historical evidence is never imported as invented database history. `--retained-replay` reads the completed controlled scenarios from the recorded failed-wrapper attempt and launches no further Workers; use ASF_P12_RETAINED_SOURCE to select that record.
6. `--performance` creates 100/1,000/6,000-file disposable fixtures, real generated Git history, bounded change sets and worktrees. It records API/status/diff/index/commit/branch/history timings and an owned server memory sample. These are local synthetic source-data measurements, not agent throughput or universal latency guarantees.
7. Run `rust` (fmt, strict Clippy, full serial Rust), `parallel` (normal-threaded Rust), `frontend` and the retained P03-P07 production browser regressions with the current copied binary. Do not run large builds concurrently when host commit memory is constrained. Preserve resource failures separately; do not suppress product assertions.

A new output can be selected with ASF_P12_OUTPUT. Inspect failures before repeating a model scenario. Screenshots require visual inspection and do not substitute for Git/API assertions. Controlled fixtures are labelled as controlled; original P08 genuine execution is reused with its original timestamps and hashes.

## Continuing a safely settled failed attempt

The retained first model attempt produced a relevant source/test patch but correctly failed command-policy validation. `--retry-model` is an explicit, bounded continuation of that existing mission, not a new Planner call or autonomous replan. It restores the actual owning workspace, preserves the refused attempt and partial worktree, and clarifies Worker reporting instructions without changing model or permissions. It requires the fixed backend's settled-task retry checks. It must not be used to clear suspended/closed sessions, uncertain processes, conflicting integration or a provider usage-limit refusal. The attempt and original refusal remain independently inspectable.

The `lifecycle` validation mode exercises the atomic retry and completed-settlement delivery boundary. The `stress` mode uses the existing scheduler stress assertions with a bounded owned loopback barrier: two actual controlled Workers must be alive before either completes. It does not measure model throughput or relax task-owner/capacity assertions.

`--inspect-model` restores the successful genuine mission selected by ASF_P12_MODEL_SOURCE (default model-retry-4), verifies unchanged session identity, rereads actual review/integration evidence and runs another independent checkout. It launches zero model processes. It qualifies final presentation and delivery-preview corrections without repeating coding work. The source record/binary hash remains linked separately. The Review preset is applied before screenshots so the diff is inspected in the intended main workspace.


The `refs` validation mode runs the native Git and authenticated API ref-alias regressions. With ASF_P12_BINARY pointing to a copied current binary and ASF_P12_REF_OUTPUT naming a fresh JSON file, `node scripts/v2_p12/ref-alias.mjs` creates its own disposable repository, verifies ordinary branch writes, then requires reserved aliases and occupied ASCII/Unicode worktree aliases to be rejected without moving HEAD. Native noncanonical worktree refs require reconciliation rather than assuming Git will protect them. `--expect-vulnerable` is only for preserving the historical vulnerable-binary reproduction; its result is explicitly `VULNERABILITY_REPRODUCED`, never a security pass. `--expect-unicode-vulnerable` records the intermediate executable's separate `UNICODE_OWNERSHIP_BYPASS_REPRODUCED` outcome; it is also never a pass. These probes accept no user repository path and perform no publication.

## Optional live remote-write qualification

Live writes are NOT authorized by this phase. First implement/review a concrete opt-in procedure naming an explicitly authorized disposable repository, head/base, allowed commit and exact external operations. Confirm effective push destination, project/lifecycle policy, reviews/tests and authenticated repository ID. Use the production delivery preview and explicit consent, inspect the actual remote result, and record PR identity. Never use the ASF development repository, force push, remote merge or production deployment as an acceptance fixture. Without that authorization, report `LIVE GITHUB WRITE ACCEPTANCE: NOT QUALIFIED - NO AUTHORIZED REMOTE MUTATION`; controlled production-provider tests remain separate.

The `focused` mode includes authenticated application-budget isolation. `api_parallel` runs all Source Control API regressions with normal test threading; it must preserve the original permission/publication-denial assertions. The eight-request Source Control budget is shared by projects of one application and independent of another application instance. The failed process-static-budget attempt remains in the evidence ledger.
