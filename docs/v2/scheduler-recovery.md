# Scheduler recovery and interruption

Cancellation is an explicit domain action. Runtime sets the owned cancellation flag and marks the durable owner Cancelling, preventing further database claims. The coordinator drains supervised Worker/Reviewer/check processes, preserves unfinished task/candidate evidence, releases RAII agent/task permits and then records Cancelled. A tab unmount, browser disconnect or project switch does not set cancellation; P10 suspension is not implemented.

Publication cannot be rolled back by pretending a concurrently completed Git mutation did not happen. The journal compares the actual run ref with the candidate before classifying an integration error or restart. A published ref is reconciled to the database; an uncertain/preparing candidate stays preserved and Interrupted. No force reset is used.

At project Runtime startup, while holding P03 ownership locks, existing session/attempt/MCP reconciliation runs. Durable dispatch owners are closed as interrupted with unknown external effects. Running/reviewing attempts become Interrupted; no Worker is silently replayed. A manual retry of an Interrupted attempt is refused until ownership is inspected; retaining a worktree is not proof the original process stopped. New repair work must use fresh task ownership. This is conservative crash reconciliation, not P10 resumable checkpoints.

In-process task panics are caught and classified; scope unwinding signals cancellation and joins task threads. Failed process launch releases reservations. SQLite operations use bounded existing busy handling and never hold write transactions over process, Git, review or Planner I/O. A terminal resource limit or deterministic policy denial is surfaced, not disguised as code-quality feedback.

Effective policy is read under established durable ownership. A setup error, including corrupt persisted policy JSON, closes that owner through a scope guard without launching an agent. Cleanup is bounded best effort if SQLite itself is unavailable; startup reconciliation remains necessary after uncertain persistence failure. Legacy runs have no newly imposed workflow-wide timeout; explicit P08 deadlines use the same stop/drain path as cancellation, preserving their distinct resource-limit result.

P08 records the real child PID and start/finish timestamps. On Windows it requires Job Object ownership before writing stdin mission input and uses kill-on-close/descendant cleanup. Argument-based transports already carry their prompt at spawn; there is no claim that those bytes were withheld before assignment. An unavailable Job Object is classified as HOST_SANDBOX_RESTRICTED without widening permissions. Unix uses process groups and descendant cleanup; native qualification remains pending. There is a short spawn-to-job-assignment window and application policy is not an OS sandbox. Host kill, kernel failure, external CLI descendants and uncertain remote side effects cannot be promised exactly once. Native Linux/macOS and crash-at-every-instruction qualification remain separate evidence gates.

A native Codex exit-one usage-limit diagnostic is classified separately as `AGENT_RESOURCE_EXHAUSTED`. It blocks the run after the first refusal, preserves any partial work, releases capacity and does not invoke another Worker or recovery Planner. This is a reported provider-availability boundary, not a policy grant or a code-quality verdict. Unknown provider failures retain the existing bounded generic failure path. Cancellation during a drain cannot overwrite the first substantive failure; an explicit user cancellation with no prior fatal error returns the actual Cancelled outcome after cleanup.

## P10 browser-managed lifecycle

New browser-managed runs have explicit project/workspace ownership. A persisted lifecycle state other than `active` fences scheduler acquisition, task claims, invocation admission, revision application and legacy start/retry entry points. Suspension signals the existing owned operation and waits for its threads, agent process cleanup and task claims to drain. It preserves all task attempts, worktrees, reviews, integration journals and P09 handoffs. Legacy unmanaged runs retain the previous recovery behavior.

A confirmed checkpoint is required for manual logical resume. Current policy, agent eligibility, Git references, worktree fingerprints and integration uncertainty are revalidated. Completed/integrated tasks remain completed. Interrupted invocations receive bounded factual context in a new execution, without model-state restoration. Scheduler active-time budgets accumulate across resumed ownership intervals; intentional suspended time does not consume that execution budget.
