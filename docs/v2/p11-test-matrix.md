# P11 verification matrix

This matrix separates automated assertions, controlled subprocess integration, and real model/browser evidence. A controlled Python agent is a process fixture, not evidence of model reasoning. Qualification is recorded in `deliveries/V2-P11.md` and `evidence/p11/manifest.json` after the checks finish.

| --- | --- | --- |

| MEM-09–10 | `mem_09`; existing factory-db migration/backup tests | Reject unknown fields and limits; additive migration 23 retains earlier tables. |

| Real models/browser | `scripts/v2_p11/preflight.py`, `scripts/v2_p11/acceptance.mjs` | Fresh provider preflight; real native Worker/source diff/review/integration; memory supplied before/after safe handoff and manual resume. Results must be read, not inferred from this procedure. |

Run targeted checks using `node scripts/v2_p11/validate.mjs memory` and `memory_resume`, with a single Cargo operation at a time. Run the full `rust`, `parallel`, `frontend`, and approved native IDE tool modes before qualification. Validation output includes both starting and ending source fingerprints; changed-source runs are not final evidence. Resource refusals and earlier failed attempts are preserved.

Explicit extractor delegation also uses core `extractor_cannot_receive_file_evidence_outside_its_resolved_read_policy`: actual role/profile resolution rejects denied repository evidence before process creation, while an allowed source still executes. The pre-fix controlled failure is retained.
